# PersonaAI Program

Updated: 2026-08-27 03:38 +05:30

## Objective

Evolve PersonaAI from a role-aware AI profile/storefront into a configurable AI Business OS composed from reusable operating engines and versioned business blueprints.

## Current Milestone: Phase 0 - Platform Orchestration Foundation

Phase 0 is complete only when the repo has a truthful orchestration ledger, a safe ownership model for the dirty checkout, clear shared contracts for the six operating engines, and dependency-aware worker packages that can be executed without touching active restaurant-order work.

## Non-Negotiables

- Keep customer-facing AI persona and owner-facing Business Copilot as separate AI planes.
- Use shared engines, not one-off industry forks.
- Treat every existing dirty path as user-owned unless proved otherwise.
- No worker edits the primary checkout.
- No pushing, deployment, production writes, external messages, secret rotation, destructive git operations, or database migrations against non-ephemeral data without approval.

## Shared Operating Engines

1. Commerce: catalog, variants, inventory, cart, order, payment, fulfilment, return.
2. Appointments: services, staff, resources, availability, deposits, reminders, waitlist, no-show recovery.
3. Content/cohorts: courses, batches, lessons, attendance, assignments, progress, certificates, memberships.
4. Venue/orders: tables, rooms/seats, reservations, QR, live queues, status history, guest tracking.
5. Field jobs: intake, quote, technician, route, asset, job card, parts, inspection, invoice.
6. Cases/projects: lead, brief, documents, milestones, tasks, approvals, deliverables, billing.

## Reference Vertical Waves

Wave 0: Coaching/training, consultants/agencies, retail/social commerce, CA/accounting, restaurant/cloud kitchen.
Wave 1: Salon/spa/wellness, home/field services, events/weddings/media, real estate/property.
Wave 2+: Blueprint-only until shared workflow, governance, integrations, and vertical safety boundaries are stronger.
